# C6 — มือถือ การเข้าถึง เมนู ค้นหา แบ่งหน้า และการกลับมาใช้งาน

ผู้สำรวจ C6 อ่าน REQUIREMENTS.md, TEST-DATA.md, USER-STORIES.md, web/SPEC.md และ web/ASSETS.md เท่านั้น ไม่อ่าน runtime source และไม่เปิด web/BUGS.md

## Oracle ก่อนเปิดเว็บ

[D] FR02/FR07 กำหนด 12 งาน แบ่งหน้า 6 งาน ค้นหาและเลือกงานได้; FR02 แยกตารางรอบตามบัญชี; FR05 ตรวจหมายเลขสมาชิกผ่านแล้วเข้าผังทันที; FR10/FR15 กู้ข้อมูลการจองได้; NFR01 ใช้จอ 375px ไม่ล้น มี label/error และเลือกที่นั่งด้วยคีย์บอร์ด; NFR02 ไม่แสดงข้อมูลส่วนตัวข้ามบัญชี

[A] SPEC อ้างธีมสว่าง แยกบัญชี กู้ checkout และไม่เปิด dialog กลับหลังผู้ใช้ปิด ระหว่างสำรวจจะเทียบกับ [O] พฤติกรรมที่เห็นจริง ไม่ใช้ภาพหน้าจอเป็นแหล่งกำหนดจำนวนหรือยอดเงิน

ใช้ dedicated instance C6 จาก ENVIRONMENT.json เท่านั้น (`http://127.0.0.1:4346`) ไม่เรียกพอร์ตผู้ใช้และไม่เปลี่ยนไฟล์ระบบ

## การลงมือและการแยกข้อมูล

- รอบผลครบ: **2026-11-06T11:17:51.365Z ถึง 2026-11-06T11:17:54.041Z** (18:17:51–18:17:54 น. ไทย)
- Chromium headless context ใหม่ ขนาด **375 × 812px** ของ C6 เอง ไม่ใช้ browser/session ร่วมกับ charter อื่น
- reset เฉพาะ C6 หนึ่งครั้งก่อนเริ่ม ไม่เรียก clock และไม่มีการเรียกพอร์ตอื่น การซื้อในกรณี mobile ใช้ข้อมูลสมมติ `C6 Mobile / c6@example.test / 0812345678`

## ข้อจำกัดและประเด็นส่งต่อ

- ตรวจ Chromium ที่ viewport 375px เท่านั้น ไม่ได้ใช้เครื่อง iPhone/Android จริง ไม่ใช่ผล Safari/Firefox และไม่ใช่การตรวจ WCAG ครบทุกข้อ/โปรแกรมอ่านหน้าจอ
- ทดสอบ Space กับปุ่มที่นั่งและ Escape กับ dialog ไม่ได้รับรองลำดับ Tab ของทุก control ในทุกหน้าจอ
- ข้อมูลการซื้อ C6 มีเฉพาะบัญชีทั่วไป/QR สำหรับพิสูจน์ mobile journey ช่องทางอื่นและการคืนเงินเป็นเจ้าของ C4/C5
- C6-03 เป็นกรณี recovery ที่อาศัยเกณฑ์ NFR01 และข้อเสนอด้านความใช้งาน จึงไม่ตีความว่ามีระบบ offline ที่เอกสารไม่เคยระบุ
- ไม่พบความต่าง D/A/O ที่ต้องแก้ runtime ใน C6 รอบนี้
